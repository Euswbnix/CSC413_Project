# 驾驶数据集调研

日期：2026-09-21。对应 [`decision_2026-09-21_keep_driving.md`](decision_2026-09-21_keep_driving.md) 的关卡 D1。

**方法。** 先从三个角度分头搜索候选：端到端转向预测文献常用的数据集、LNN/NCP 驾驶论文实际使用的数据、2019 年以来带车辆 CAN 信号的数据集。
去重后得到 18 个候选，逐个对照官网、论文、代码仓库和许可文件核实，最后排序。排名第一和第二的关键事实又抽查了原文。

- **【已核实】**：读过官方页面、论文原文或代码
- **【未核实】**：页面没写、无法访问，或只来自二手资料

**要求**（按优先级）：
1. 有多个独立行程，能按行程或路线划分；
2. 有逐帧时间戳，帧率 ≥ 约 10 Hz；
3. 有与画面同步的转向角，或可以替代它的信号；
4. 道路有真实的弯道，不能只有高速公路。

## 结论

**主数据集：Honda HDD（待申请）。备选兼复现数据集：nuScenes + CAN 扩展包。可选的第三个：Zenseact ZOD。三个的申请现在就同时发出去。**

**决策节点：** 若到 **2026-10-05** 仍拿不到 HDD，就改用 nuScenes 作为主数据集，历史窗口缩短到 4–5 秒以内。

**开发顺序：** 流水线先在 nuScenes 上搭，因为它最可能最早拿到，包括冻结特征、按真实时间间隔切窗口、丢帧、全部时序模型。HDD 到手后再移植过去。

**不要把几个数据集混在一起训练主模型。** 它们的转向比、正负号约定、相机和帧率都不一样。更好的做法是在 HDD 上跑主实验，在 nuScenes 上用同一协议复现，比较两边模型的排名是否一致。

## 划分方案

**HDD：按地理位置划分，而不是按会话。**
1. 如果发布版附带论文的地理测试划分（37 个会话），直接用它作为 test。
2. 否则，把 GPS 轨迹划进约 1–2 km 的网格，按网格整块分配给 train、val、test（约 63/12/25%）。val 和 test 中离训练轨迹 50 m 以内的帧删掉，或者单独报告。
3. 检查每个划分里都有城市和郊区的弯道路段，不能只有高速。
4. 在任何模型训练之前固定划分，并提交会话清单。

**nuScenes：按日志整段分配，并按地点分层。**
- 只用 trainval，因为 test 划分有没有 CAN 数据【未核实】。
- 84 段日志按地点分层，大约 60/12/12。
- 固定划分之前，先量一下各划分之间的轨迹重叠。
- 更严格的次要测试：留出一个新加坡子区域。波士顿与新加坡之间的迁移，只能作为单独的领域偏移结果报告，因为它和左右行驶混在一起。

## 第一周要做的检查

拿到数据后逐项确认：

1. **清单**：会话数、总大小、是否附带 GPS 和地理划分清单、时间戳文件的格式。
2. **时间戳**：画出每段录像相邻帧的时间间隔分布，确认标称帧率，找出丢帧和抖动。丢帧实验依赖真实的时间间隔。
3. **转向的单位和正负号**：在已知的左转、右转处，把转向角和横摆角速度、GPS 航向变化画在一起对照。
4. **转向角分布**：确认有足够的弯道样本，不会重演 SullyChen 那种直行主导的情况。
5. **帧与标签同步**：100 Hz 的转向信号插值到帧时间，抽样目视核对。

## 可以引用的相关工作

- **Lechner 等 2020（NCP，Nature Machine Intelligence）**：在被动转向预测上，LSTM 与 NCP 相当甚至略好（3.17 对 3.22）【已核实】。这说明在帧率充足的条件下，液态网络未必有优势，所以应该去测"观测变稀疏"的条件。
- **Hasani 等 2022（CfC）**：驾驶实验里 CfC 与 LTC 只做了定性比较，驾驶数据没有公开。
- **Ben Naveed 等**：在 comma.ai 2016 上用 NCP 做转向，没有 LSTM 对照，也没有不规则采样实验。

## SullyChen 数据的角色

- **SullyChen 2018**：只作探索和调试用，不作为研究问题的证据。可以用来：
  - 在新数据到手前做流水线的冒烟测试；
  - 记录这次转向的动机，即模型在同一段录像的不同路段之间泛化失败；
  - 统一单位和正负号之后，作为一个单独报告的域外测试集。
- **SullyChen 2017**：没有时间戳，不能用于丢帧实验。

## 公开仓库的规则

数据和提取出的特征文件**一律不入库**。只提交代码和划分清单（会话 ID、日志 ID）。
