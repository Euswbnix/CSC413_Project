# 决定：撤回 HAR 方案，保留自动驾驶主线

日期：2026-09-21（同日第二份决定）。

**状态：本决定取代 [`decision_2026-09-21_redesign.md`](decision_2026-09-21_redesign.md) 中"更换主实验任务"的部分。**
那份记录里的证据、评测纪律和统计方法仍然有效，但主实验不再换成手机活动识别。两份文件都保留，因为转向的过程本身就是报告的一部分。

## 为什么撤回

项目的目标是研究**液态神经网络（LNN）在自动驾驶中的应用**。HAR 方案把问题换成了一个更容易的任务，
做得再干净，回答的也是另一个问题。之前提出 HAR，是过于看重降低实验难度，没有充分保留这个应用目标。

原来的驾驶研究框架值得保留：驾驶视频 → 视觉特征 → 时序网络 → 转向角，再比较 LSTM、CfC、LTC。
已有的时间顺序划分、参数量控制、单帧与时序模型对照，也都有价值。

## 现有驾驶实验的四个限制

1. **还没有一个有竞争力的预测模型。** CfC、LSTM 在 test 上的平均 macro MAE 约为 13.94°、13.65°，而在验证集上拟合的常数是 12.92°。
   在学习和泛化都不足的情况下，比较架构的解释空间很有限。（[结果](results_2026-09-21_v2_metrics.md)）
2. **同一段录像按时间切分，不足以代表跨道路泛化。** 多跑随机种子只能了解训练波动，不能增加独立的道路、天气和驾驶场景。
3. **视觉编码器与时序模块的影响混在一起。** 表现不好，可能来自视觉特征、标签分布、训练目标或循环模块。
   消除 CfC 的门饱和之后表现没有一致改善，所以门饱和不能当作已确定的原因。（[诊断第 17 节](diagnosis_2026-09-20.md)）
4. **目前是离线转角估计。** 输入视频不会随模型的预测而改变，即使连续播放并传递隐藏状态，也没有形成控制闭环。
   所以它能研究驾驶预测能力，但不能直接证明车辆开得更稳、更安全。

## 新的研究问题

**在驾驶视频的转向角预测中，LTC 与 CfC 相比于获得同样时间信息的 LSTM，是否在观测变稀疏时具有更好的精度与计算成本取舍？**

正常条件下持平、丢帧时出现差异、始终没有优势，这几种结果都能回答同一个问题。

这里的"计算成本"只指**时序模块本身**，而且要在相同的实现方式下比较。原因有两点：
- 实测表明，cuDNN 的 LSTM 比我们用 Python 循环写的 CfC 快约 100 倍，这主要是实现方式的差异，不是模型结构的差异；
- 在整条流水线里，冻结的视觉编码器才是延迟的大头。

## 新设计

| 部分 | 做法 |
|---|---|
| 数据 | 优先使用包含**多个独立行程**、带时间戳和转向角标签的驾驶数据，**按行程或道路留出**。推断的单位是行程，不是帧。调研进行中。 |
| 视觉前端 | 第一阶段所有模型共用**同一套冻结的预训练视觉特征**，只算一次并缓存。输入用完整画面，按该预训练模型要求的分辨率和归一化处理，不再沿用切掉地平线的 66×200 裁切。 |
| 核心模型 | 单帧 MLP、LSTM+Δt、CfC、LTC；Transformer 保留，承担参照和 Advanced Concept 的作用。 |
| 核心条件 | 完整视频；近均匀地减少历史帧；随机删除历史帧。 |
| 公平性 | 固定预测时刻、目标标签和历史时间跨度；各模型获得同样的观测和真实时间间隔；参数量配平。 |
| 指标 | 事先确定的转角误差、弯道表现、输出是否跟随真实转角变化（例如 CCC），以及实测延迟。 |

**冻结特征这一步最关键。** 在现有实验里，CNN 和时序模块一起训练时，训练集误差下降、验证集误差回升。冻结编码器可以带来三个好处：
- 所有时序模型读到完全相同的特征，视觉因素被隔离开；
- 编码器没法再"背下训练路段"；
- 时序模型的训练变得很便宜，种子数不再是瓶颈。

但冻结特征本身也可能不够好，必须先通过验证。不能因为用了预训练模型，就默认视觉问题已经解决。

## 顺序与关卡

**先让一个简单的驾驶基线正常工作，再比较时序架构。**

| 关卡 | 通过条件 |
|---|---|
| D1 数据 | 找到有多个独立行程、时间戳、同步转角的数据，能按行程或道路划分 train/val/test |
| D2 有效基线 | 冻结特征 + 简单预测头，在留出行程的验证集上**稳定赢过验证集常数**，而且输出确实随真实转角变化，而不是近似常数 |
| D3 丢帧有效 | 删除历史帧会让基线的表现可测量地下降，否则这个条件区分不了模型 |
| D4 比较 | 以上都通过后，预注册 LSTM+Δt、CfC、LTC 的比较，再在从未用于选择方案的行程上做确认 |

**LTC 排在有效基线和 Transformer 之后，设硬性时间上限。** 直接使用 ncps 1.0.1 的 LTC 有四个已经核实的坑，必须先处理：

| 问题 | 处理办法 |
|---|---|
| batch 大小等于隐层数（64）时，时间间隔会被静默错配到别的样本上（GitHub PR #85 至今未合并） | 逐步调用 LTC 单元，把间隔按 `(B,1)` 传入。已验证批内结果与逐样本运行一致 |
| Δt = 0 会产生 NaN | 不用 0 填充；每个 batch 只用同一种删点率 |
| 反转电位的初始化固定在种子 1111 上，各 seed 实际共享这部分初始化 | 构造时传入 `FullyConnected(64, erev_init_seed=<run seed>)` |
| LTC 未必真的在使用 Δt | 训练后用同一组权重，分别以真实 Δt 和 Δt = 1 评估，确认 Δt 确实起作用 |

另外：隐层 64 时，LTC 与 CfC 的参数量天然配平（24,960 对 24,832），计数时要排除 6,144 个冻结掩码；LTC 比 CfC 慢约 6.6 倍（实测）。

**仿真闭环是加分项，不是默认内容。** 如果更关心"模型能不能实际控制车辆"，可以做一个范围很小的仿真闭环：固定目标速度的车道保持，
模型只控制方向，速度控制器保持一致；比较车道偏离、路线完成率和碰撞。但要注意，在真实视频上训练的模型不能直接放进仿真器开车，
画面差异太大，闭环实验需要在仿真器里另外采集数据、重新训练，实际上是另一个实验。仿真器对显存和内存的需求也要和共享服务器上的其他服务协调。
因此只做一次 **2–3 天**的限时可行性检查：接入顺利，就可以成为重点；成本过高，就只做严格的离线预测研究，并把结论限定在预测能力上。

## 旧数据的用法

- SullyChen 2018 的旧 test 集已经被反复查看，只能继续用于探索和诊断。新的确认性结论必须来自此前没有参与方案选择的行程。
- SullyChen 2017 是另一段录像，但没有时间戳，而且可能和 2018 覆盖同一区域（见 `REVIEW.md` 第 604 行）。它**不能**当作独立行程，
  最多用于一次标注为"跨录像、同区域"的只推理检查。

## 对课程要求的影响

- **研究主题没有改变**，仍然是 CfC 与 LSTM 在驾驶上的比较。教授此前的两条裁定（CfC 可以作为 RNN 组件、固定窗口满足变长要求）继续适用。
  给教授的邮件从"申请换题"改为"告知会更换或补充数据集、新增 LTC 对照"。审查文档附录 A 那份换题邮件草稿不再使用。
- **Advanced Concept**：Transformer 仍然是主要候选；原来的域适配增强是否算数，教授的回答仍是"不确定"。
