# D4 预注册

日期：2026-09-22。状态：**已定稿**（试跑与方差估计完成后定下等价界和 seed 数）。**定稿之后不改；测试集在最终评测之前不碰。**

D1–D3 已通过：[第一周检查](hdd_week1_checks_2026-09-21.md)、[D2](results_2026-09-22_d2.md)、[D3](results_2026-09-22_d3.md)。

## 1. 研究问题与假设

**问题**：在驾驶视频的转向角预测中，LTC 与 CfC 相比于获得同样时间信息的 LSTM，在观测变稀疏时是否具有更好的精度与计算成本取舍？

两个假设分开，**不能互相替代**：

| | 假设 | 说明 |
|---|---|---|
| **主假设 H-A** | 在预先指定的稀疏条件下，CfC（以及 LTC）的 macro MAE 低于 LSTM+Δt | 这是主比较，检验"稀疏时更准" |
| **次假设 H-B** | 从完整历史到稀疏条件，CfC / LTC 的相对退化小于 LSTM+Δt | 鲁棒性补充。**本身预测就差的模型也可能退化很小**，所以 H-B 单独成立不算支持主问题 |

主比较的条件：**随机删除 75% 的历史观测**（当前帧始终保留）。删 50% 和完整历史作为次要条件一并报告。

## 2. 模型与参数配平

所有模型共享同一套冻结的 DINOv2 ViT-B/14 特征（3 s 历史、10 Hz 基础率、30 步），共享同一结构的投影层和读出头，只有时序模块不同。

| 模块 | 可训练参数（实测，输入 64、隐层 64） |
|---|---|
| 共享投影 Linear(1536 → 64) | 98,368 |
| LSTM+Δt：LSTM(65 → 64) | 33,536 |
| CfC（本仓库手写） | 33,024 |
| LTC（ncps 1.0.1，全连接接线） | 33,216（另有 8,192 个冻结掩码，单列不计入） |
| Transformer（最小实验，配置待定） | 待定，按同一口径报告 |
| 共享读出头 Linear(64 → 1) | 65 |

- 三个时序模块相差在 1.5% 以内，是隐层 64 下的自然配平，不额外调整。
- **参数量按模块分列报告**（投影 / 时序 / 读出），不能只报总数，也不能只凭"隐层都是 64"就说配平。
- ncps 自带的 CfC 在同样配置下是 49,536，不用它；用仓库里手写的那个。

## 3. 训练与评测

- **训练**：混合采样增强——每个 batch 抽一种删点率（0 / 50% / 75%），同一 batch 内只用一种（LTC 的 Δt = 0 会产生 NaN）。所有模型用同一份数据、同一增强协议，各自独立训练。
- **评测**：同一 checkpoint 在三种条件下评测，只删历史观测，当前帧保留，Δt 按保留下来的帧重算。
- **窗口规则收紧**：窗口内最大步长 ≤ 0.2 秒（D3 用的是总跨度上限，训练集有 1.54% 的窗口因此混入断档）。
- **目标帧**：与 D2、D3 相同（车速 > 3 m/s、标签不跨 CAN 断档）。
- **补充条件**：原始时间戳断档（自然丢帧）的样本单独评测，只报告，不进主检验。
- **调参预算**：每个模型族 4 次选学习率（{1e-3, 3e-4, 1e-4, 3e-5}，各 1 个 seed）+ 8 个 seed 确认，最多 60 个 epoch、早停 patience 8。选学习率和早停都按三种条件下 macro MAE 的平均值。

## 4. 指标

- **主指标**：macro MAE（按 |转角| 分 < 5°、5–15°、≥ 15° 三档平均，`metrics.macro_mae`）。
- **次指标**：CCC、逐档 MAE、实测计算成本（同设备、同精度、同 batch、预热后同步计时；单窗口延迟与批量吞吐分开报，注明实现方式）。
- 主统计量：两个模型在**同一批目标帧**上的 macro MAE 之差（按帧加权），并按路线簇分解。

## 5. 统计方法与功效（定稿前必须先做试跑）

**不能直接用 D3 的方差估功效**：D3 只有 MLP 和 LSTM 的总体分数，没有配对差值，也没有区分 seed、路线簇、删帧掩码三种波动来源，而且没有经过混合采样训练。

**试跑已完成（2026-09-22，见 [`results_2026-09-22_d4_pilot.md`](results_2026-09-22_d4_pilot.md)）**：LSTM+Δt 与 CfC 各 3 个 seed，混合采样训练，保存了 19 万个目标帧的逐帧预测，每个删帧条件另用 5 组随机掩码。

配对差值（CfC − LSTM，macro MAE 度数）的方差分解：

| | 删 75%（主条件） | 完整历史 |
|---|---|---|
| 平均差值 | +0.210 | +2.034 |
| 跨 seed 标准差 | 0.178 | 0.175 |
| 同一 seed 内跨掩码标准差 | 0.035 | — |
| 跨路线簇的贡献标准差 | 0.069 | 0.219 |
| seed × 路线簇 bootstrap 95% 区间 | [−0.181, +0.620]，半宽 0.401 | [+1.078, +3.107]，半宽 1.015 |

**据此定下（不再更改）：**

- **等价界 δ = 0.5°**（约为主条件下 16° 的 3%）。理由：混合采样训练之后，删 75% 给 LSTM 带来的退化只有 0.38–0.65°；等价界不能大过我们要研究的效应本身，所以 1.0° 太宽，取 0.5°。
- **最终 seed 数 n = 8**（每个模型族）。外推半宽 0.245°，若真实差值在 +0.21 附近，区间上界约 0.45°，仍落在 ±0.5 之内；n = 3 的半宽 0.401 不够。测试集有 16 个路线簇（验证集只有 7 个），簇那一部分的波动还会更小，所以这个估计偏保守。
- **掩码不是瓶颈**：同一 seed 内跨掩码的标准差只有 0.035°，最终评测每个条件用 5 组掩码取平均即可。
- **训练预算随之放宽（对所有模型族对称）**：学习率网格加到 {1e-3, 3e-4, 1e-4, 3e-5}，每个 1 个 seed；最多 60 个 epoch、早停 patience 8。理由：试跑中 CfC 选中了网格最小的 1e-4，且有一个 seed 跑满 30 epoch 才停，说明原预算把它卡住了。选学习率和早停都用三种条件下 macro MAE 的平均值。
- **判定规则**：主统计量是删 75% 条件下 CfC 与 LSTM+Δt 的配对 macro MAE 差值，按路线簇分解，用 seed × 路线簇两层 bootstrap 给 95% 区间。
  - 区间完全落在 ±δ 之内 → 报告"实际等价"；
  - 区间不含 0 → 报告"有差异"，并给出方向和大小；
  - 其余 → 报告"未能区分"，不写"等价"。

**统计形式（拟定）**：
- 配对差值先在 seed 和掩码上平均，再按路线簇汇总；主检验用 seed × 路线簇的两层重采样。
- 敏感性分析：按会话聚类、按日期聚类。**若结论随聚类方式改变，如实报告敏感性，不取更显著的那个。**
- 等价界 δ 在看到任何测试集结果之前写定，且不得根据试跑结果放宽。功效不足时，报告"未能区分"，不写"实际等价"。
- 多重比较：主检验只有一个（H-A，在 75% 条件下 CfC vs LSTM+Δt）。LTC vs LSTM+Δt、LTC vs CfC、H-B 以及各条件曲线属于次要族，统一做 Holm 校正。

## 6. LTC 的额外要求

沿用[决定记录](decision_2026-09-21_keep_driving.md)的 LTC 表：batch 等于隐层数时的 Δt 错配、Δt = 0 的 NaN、`erev` 初始化固定种子、Δt 是否真的起作用，以及 2026-09-23 发现的第五条——每次优化步后必须调用 `apply_weight_constraints()`，否则参数变负、ODE 发散。另加：

- **积分子步数敏感性**：同一组权重，在最大间隔条件下分别用 6、12、24 个子步评测，结果明显变化就改用更细的积分重训。这是固定权重下的数值检查，不是三个独立模型的比较。
  - **判定标准（2026-09-24，检查运行之前写定）**：用 seed 0 的训练权重，在删 75% 条件下各取 5 组掩码的平均。若 6 与 24 个子步的验证 macro MAE 相差超过 **0.1°**（等价界 0.5° 的五分之一），判定积分未收敛，全部 LTC 改用 24 个子步重训；否则维持 6 个子步。只做这一轮检查，不在多个子步设置之间挑选。
- 若预算内得不到稳定结果，把 LTC 标为"未完成有效比较"，不能把粗积分的低分写成 LTC 能力不足。
- LTC 与 CfC 的差异不能只归因于"数值积分 vs 闭式近似"，两者不是同一网络的严格等价实现。

### 运行中的补充规则（2026-09-23，LTC 重跑之前写定，对所有模型族一样）

- 训练中出现非有限的损失或验证分数，立即停下，记为"发散"，保留发散之前最好的状态，不当作"没有改进"继续计数。
- 学习率网格里发散的格点**不参与**选择，无论它发散前的分数多好；四个格点都发散，就按上面的规则把该模型族标为"未完成有效比较"。
- 2026-09-22 至 23 的第一轮 LTC 结果（学习率网格 4 个格点、正式训练 3 个 seed）是在没有参数约束的情况下训练的，全部作废，
  文件保留在服务器的 `~/data/hdd/d4/invalid_ltc_no_weight_constraints/`，不进入任何分析。LSTM+Δt 与 CfC 不受影响。

### 积分子步数检查的结果（2026-09-24）：未通过，LTC 全部改用 24 个子步重训

按上面写定的规则，用 seed 0 的训练权重在验证集上评测（删 75% 条件各取 5 组掩码的平均）：

| 积分子步数 | 删 75% | 完整历史 |
|---|---|---|
| 6（原设置） | 17.563 | 17.141 |
| 12 | 17.725 | 17.133 |
| 24 | 17.961 | 17.147 |

- 6 与 24 在删 75% 条件下相差 **0.398°**，超过 0.1° 的门槛，判定积分未收敛。完整历史下三者几乎一样，说明问题出在观测间隔大的时候积分太粗——正是这项检查要防的情况。
- 按规则，**全部 LTC 改用 24 个子步重训**，学习率网格也重跑（在 6 个子步下选出的学习率不一定适用）。6 个子步的全部结果（网格 4 个格点、seed 0 完整、seed 1–7 各到第 8 个 epoch）留档在服务器的 `~/data/hdd/d4/ltc_unfolds6_superseded/`，**不进主比较**。
- 24 个子步时单个 LTC 进程要约 11.4 GB 显存（反向传播要保存每一步积分的中间结果），所以最多同时跑 2 个；批大小仍是 256，不因显存而改动，保持各模型族的训练协议一致。
- 预计耗时明显变长。由于每个 epoch 都有检查点，可以跨多个晚上续跑。

### LTC 改用编译后的积分单元（2026-09-24）

- 24 个子步时原生实现太慢（每个 epoch 约 18 分钟）、显存太大（每进程约 11 GB），所以用 `torch.compile` 编译 ncps 的 LTC 单元（输入映射、24 步积分、输出映射）。**数学完全不变**，用的仍是 ncps 自己的代码，差异只来自浮点运算的顺序。
- 验证（`hdd/ltc_compile_check.py`，在真实窗口上，6 种不同 batch 大小，训练与评测交替）：训练输出最大相对误差 1.1×10⁻⁶，所有参数梯度 1.3×10⁻⁵，评测输出 1.1×10⁻⁶；只编译了 3 张图，计时之后没有增加，说明没有悄悄退回原生模式。
- 效果：每个训练步从 114.9 ms 降到 18.9 ms（快 6.1 倍），峰值显存从 9.37 GiB 降到 0.53 GiB，所以 4 个网格点可以同时跑。
- 学习率 1e-3 和 3e-4 的第 1 个 epoch 是原生实现训练的，3e-5 的前 4 个 epoch 是在一次静态形状编译的尝试中训练的；之后都用动态形状编译版从检查点续跑。数值一致，所以不影响结果，这里如实记录。
- 编译只影响训练速度。第 4 节的计算成本比较另行测量，届时三个模型族要用同一种实现方式计时。
